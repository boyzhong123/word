# 小程序内存滞留与播放器卡顿修复设计

## 目标

以最小改动降低已确认的两项风险：

1. `media` 组件卸载后仍被 `scoring-session` 的 `fallbackMedia` 引用。
2. 播放器 `onTimeUpdate` 高频广播时，听力页面重复通过 `setData` 下发完整 `units` 和 `tracks`。

不调整页面样式、播放与录音流程、接口、路由或业务规则。

## 方案

### 清理评分组件引用

扩展 `clearMediaPointers(media)`：当 `fallbackMedia === media` 时同步置空。组件仍通过现有 `detached` 生命周期调用该函数，不新增生命周期或全局监听。

### 缩小播放器视图更新

播放器快照结构保持不变，避免影响现有订阅者。听力页面和听力覆盖层在收到快照后：

- 每次只更新播放状态、进度和当前时间等轻量字段。
- 仅当 `units` 或 `tracks` 的引用发生变化时，才把对应数组加入 `setData`。
- 保留切换关卡、切换音轨、引导启动和滚动定位的现有行为。

自定义 TabBar 已只更新轻量字段，不改动。

## 测试

先增加失败测试，再实现修复：

1. 已登记为 fallback 的组件在清理后不能再被路由到。
2. 同一份 `units`、`tracks` 的连续播放器快照不能重复进入页面 `setData`。
3. 数组引用变化时仍必须下发新列表。
4. 运行媒体、播放器和听力相关测试；最后运行完整测试并区分既有失败与新增回归。

## 风险控制

- 不修改播放器事件注册和音频 Context 生命周期。
- 不改变快照公开字段。
- 不做节流或改变 `onTimeUpdate` 频率，避免进度条行为变化。
- 不重构现有页面，只加入引用比较。
