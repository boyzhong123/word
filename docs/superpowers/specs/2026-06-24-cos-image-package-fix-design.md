# COS 图片与小程序包体修复设计

## 目标

修复微信真机调试 `source size exceeded max limit 4MB`，并确保页面实际使用的大图完整上传到腾讯 COS，不再依赖被排除出上传包的本地文件。

## 方案

采用“远程图片 + 本地镜像 + 上传忽略”方案：

1. 找出 `images/` 中页面实际引用且体积较大的图片。
2. 将这些图片复制到 `vercel-assets/` 对应路径，作为可重复上传的镜像。
3. 上传缺失或内容已变化的对象到现有腾讯 COS 存储桶。
4. 在 `utils/image-host.js` 中登记远程路径和缓存版本；删除已经上传图片的强制本地配置。
5. 在 `project.config.json` 中排除所有已远程托管的大图。
6. 保留小图本地加载，不进行无关迁移。

## 一致性与失败处理

- 只有 COS 对象上传成功并校验可访问后，才允许图片切换为远程加载。
- 远端对象大小必须与本地源文件一致；内容更新时同步更新缓存版本。
- 页面引用但尚未上传的图片继续保留在包内，避免出现空图。
- 审计脚本检查白名单、上传忽略、镜像文件和估算包体，任一环节缺失即失败。

## 验收标准

- 项目图片审计通过。
- 估算小程序源码包小于 4096KB。
- COS 上所有迁移图片返回 HTTP 200，且文件大小与本地一致。
- 当前更新的 PK 雪碧图覆盖 COS 旧版本。
- 新手引导、首页、入门测和会员页图片均通过 `imageUrl()` 使用远端地址。
- 现有自动化测试通过。
