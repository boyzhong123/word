三种邀请方式与小程序机制

方式小程序机制参数与获取说明 / 限制
海报小程序码 后端调微信 wxacode.getUnlimited 生成带参小程序码，前端 Canvas 合成海报 scene: "i=A7K2MQ"（≤32 个可见字符）；扫码后落地页 onLoad(options) 读 options.scene（需 decodeURIComponent）；场景值 1047/1048/1049 数量不限，适合海报；page 参数必须是已发布版本存在的页面（体验版可用 check_path=false）；生成需后端 access_token，前端只拿图
微信分享卡片 邀请页 / 海报弹窗按钮 open-type="share" 触发 onShareAppMessage path: "pages/onboarding/onboarding?inviteCode=A7K2MQ"；点卡片进入后 onLoad(options) 直接读 query；场景值 1007/1008 现有技术文档口径是分享「不带邀请 scene」，本功能上线后仅邀请场景的分享带码，其余页面分享保持不变；朋友圈 onShareTimeline 只支持 query 不支持自定义 path
手动输入邀请码 新手引导第 3 步输入框（其他方式的兜底，也覆盖「口头/群里报码」场景） 失焦调 GET /invite/validate?code= 回显邀请人昵称 6 位大写字母+数字（去掉 0/O/1/I 易混字符），由后端按 userId 生成、全局唯一

绑定规则

  • 只对新用户生效：已完成新手引导的老用户，再扫别人的邀请码不建立关系（可考虑 toast 提示「仅新用户可绑定邀请关系」）。
  • 引导完成即锁定：点「完成，开始学习」或「跳过」时，以当时填写的邀请码为准提交绑定；之后邀请页只读展示，不可修改。
  • 锁定前随便改：扫 A 的码进入、引导里改成 B 的码，最终绑定 B；清空则不绑定。多次扫码以最后一次为准预填。
  • 不能填自己的邀请码；邀请码校验失败不阻塞引导完成（按未填处理）。
  • 邀请状态两档：待完成引导（已进入/已预填但未完成）、邀请成功（完成引导锁定）。「待完成」是否展示给邀请人可再定，展示能增强反馈感。
  • 奖励体系本期不做承诺，页面文案先以「一起学」为主；后续接奖励（会员天数/学习道具）时在 hero 区和记录行加奖励字段即可。

数据与接口草案（后端）

接口用途要点
GET /mini-app/invite/summary邀请页数据返回我的邀请码、邀请人（昵称/头像/时间/来源）、邀请记录列表（昵称/时间/来源/状态）、成功计数
GET /mini-app/invite/validate?code=校验邀请码返回邀请人昵称+头像用于引导页回显；自邀/不存在返回错误码
POST /mini-app/invite/bind完成引导时绑定入参 code + source(qrcode/share/manual)；服务端校验：新用户、非自邀、未绑定过；成功后不可变更
GET /mini-app/invite/qrcode取带参小程序码服务端调 getUnlimited（scene=i=码，page=引导页），可按 userId 缓存图片 URL
